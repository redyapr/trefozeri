Public Data API

Every number on the dashboard — price candles, S/R zones' source data, the signal track record, the news calendar — comes from plain static JSON files this site already publishes to serve itself. There's no separate "API" to opt into: what the dashboard fetches, you can fetch too.

AuthNone — no API key, no login
Rate limitNone enforced, but cache client-side — see below
FormatJSON, served with open CORS (static GitHub Pages hosting)
Update cadencea GitHub Actions cron runs every 5 minutes, but H1/H4/D1 candles are only that fresh individually every 15/60/360 minutes respectively — see below

Base URL

https://redyapr.github.io/trefozeri/data/

Every endpoint below is a path under this base — e.g. {base}/signal-history.json.

GET /signal-history.json

The full shared signal track record — every BUY/SELL LIMIT signal ever recorded for XAUUSD and BTCUSD (H1 only), from pending through to its outcome. This is the single source of truth behind the dashboard's own "Signal Track Record" modal, its CSV export, and the daily/weekly Telegram reports — nothing is filtered out before it reaches you. 

[
  {
    "key": "XAUUSD-H1-Support-buy",
    "symbolKey": "XAUUSD",
    "tf": "H1",
    "category": "Support",       // "Support" | "Resistance" | "SBR" | "RBS"
    "strengthLabel": "Strong",   // "Strong" (Golden/Diamond Zone) | "Medium" — omitted on older records
    "direction": "buy",          // "buy" | "sell"
    "entry": 4301.2,
    "sl": 4295.8,
    "tp": [ { "price": 4310.5, "rr": 1.7 }, ... ],
    "openedAt": 1755300000000,   // epoch ms, when this row was first recorded
    "filledAt": 1755301800000,   // present once status has passed "pending"
    "status": "win",             // "pending" | "running" | "win" | "loss"
    "closedAt": 1755309000000,   // present once status is "win"/"loss"
    "exitPrice": 4310.6,
    "hitTpIndex": 0               // which tp[] entry was reached, on a win
  },
  ...
]

A row's life: pending (limit order placed, not yet reached) → running (price reached entry) → win/loss (price reached a tp[] level or sl). A pending row can also simply disappear if its underlying level was invalidated before ever filling — it was never a real trade. See src/lib/signalHistoryCore.js in the source repo for the exact state machine.

GET /quote/{SYMBOL}-{TF}.json

OHLC candles behind the dashboard's own chart and zone detection. SYMBOL is XAUUSD or BTCUSD; TF is H1, H4, or D1 — e.g. /quote/XAUUSD-H1.json. 

{
  "status": "ok",
  "values": [
    { "datetime": "2026-08-15 19:50:41", "open": 4300, "high": 4301, "low": 4299, "close": 4300.5 },
    ...
  ]
}

datetime is UTC, "YYYY-MM-DD HH:mm:ss" (no offset — always treat it as UTC, not local time). Gold comes from Twelve Data; Bitcoin from Binance.US, reshaped into the same schema so both symbols are consumable identically. BTCUSD candles also carry a volume field (real traded base-asset volume, from Binance.US); XAUUSD omits it entirely — Twelve Data's spot feed has no volume data to report. H1/H4/D1 are each only refetched from upstream every 15/60/360 minutes respectively (to stay within Twelve Data's free-tier request budget) — the file itself is rewritten every cron run either way, just often with byte-identical content, so match your own polling to the timeframe's own cadence rather than the cron's.

GET /quote/{SYMBOL}-latest.json

The single freshest tick available — derived from 1-minute candles fetched every run (unlike H1/H4/D1 above, which are throttled to their own slower cadence to stay within Twelve Data's free-tier request budget), but reduced to just one point rather than shipping the whole minute-by-minute series for a number this small. This is what the dashboard's own spot-price display and chart price marker read; zone detection and signals still use H1's own close, not this. 

{ "time": 1755248400000, "close": 4302.7 }

time is epoch milliseconds (UTC).

GET /calendar.json

The upstream ForexFactory-style economic calendar feed, passed through mostly as-is. The dashboard's own news banner only ever reads country, impact, date, and title — filtered client-side to high-impact USD events — but every field the upstream feed provides is present. 

[
  { "title": "Non-Farm Payrolls", "country": "USD", "date": "2026-08-15T12:30:00-04:00", "impact": "High", ... },
  ...
]

Usage notes

  • Cache it. H1/H4/D1 candles only actually change every 15/60/360 minutes respectively — polling more often than that just re-fetches the same bytes. -latest.json and calendar.json are worth polling closer to every 5 minutes instead, since they're refreshed on every cron run. The dashboard itself polls everything every 5 minutes regardless and just accepts the occasional no-op response for H1/H4/D1 — a fine trade for staying simple, but not necessary if you're building something request-conscious.
  • No SLA. This is a hobby project's own static export, not a maintained public API — treat an occasional stale or missing file as expected, not a bug to report against uptime.
  • Free to use. Attribution (a link back to the dashboard) is appreciated but not required.
